# 视觉目标卡 · 病案编码证据对照系统

> **本轮不具备图像生成能力** → 本文件只提供**结构化视觉目标卡**，**不放任何图片文件、不放占位图**。
> Phase 4 收尾采集真实运行截图到 `docs/screenshots/`，README「概念 / 实测对照」一节如实标注「哪一侧是目标、哪一侧是实测」，并写清差距。
> 画面类型：**桌面窗口**（Java 17 + Swing 窗口 + 系统托盘），不是终端、不是浏览器。

## ① 起始态（刚启动，还没有任何证据）

**画面构成**

- 一个中等尺寸 Swing 窗口（约 1100×720），标题「病案编码证据对照系统」。
- 左上角**住院号输入框**（默认空，焦点在框内）+「复核这份病案」主按钮。
- 窗口下半部是一张**空的三栏对照表**（首页编码 / 影像证据 / 判定）：表头已画好，没有数据行。
- 底部状态栏写着「待接入：PACS QIDO、RIS MLLP」。
- 系统托盘里有一个**灰色**小图标（程序化绘制，非外部图片）。

**视觉语言**

| 项 | 值 |
|---|---|
| 底色 | `#F5F6F8`（冷灰） |
| 卡片 / 表格底 | `#FFFFFF` |
| 表头 | `#3C4450`（深灰，白字） |
| 正文 | `#1F2328` |
| 强调蓝（主按钮 / 链接） | `#1A6FD4` |
| 冲突红 | `#C0392B` |
| 待确认琥珀 | `#D68910` |

| 留白密度 | 偏紧；表行高 28px，表格占满窗口约 2/3 |

## ② 首个可用瞬间（一份病案已拉回，差异已判出）

**画面构成**

- 同一个窗口，住院号已填。
- 右上角出现三枚**计数器**：检查 2 / 报告 1 / 差异 3。
- 对照表填上数据行：
  - **左栏**：首页编码，如「主诊断：肺炎（J18.9）」；
  - **中栏**：证据行，如「胸部 CT：右下肺实变影」+ 来源标记 `QIDO-RS` 或 `HL7 ORU^R01` + 证据哈希前 8 位；
  - **右栏**：判定徽章「**部位不一致**（编码缺侧别）」+ 一行灰色归因小字「报告未更新，首页缺侧别」。
- 每行右侧两个按钮：「采纳建议」「驳回」。
- 建议文本在下方明细区以可编辑文本框呈现，**未确认前不可提交**，底部「提交复核记录」按钮为**灰态**。

**视觉语言**

| 项 | 值 |
|---|---|
| 徽章底 / 字 | 冲突 `#FDE7E6` / `#C0392B`；等价 `#E8F1FD` / `#1A6FD4`；待确认 `#FDF3E3` / `#D68910` |
| 徽章画法 | 浅底 + 同色描边（`DefaultTableCellRenderer` 画色块，**不引入图表库**） |
| 差异行标记 | 左栏单元格带 2px 左侧红色竖条 |
| 明细区 | 留白大（行高 22px） |
| 信息层级 | 计数器 → 差异行徽章 → 归因小字 |

## ③ 成形态（一天下来，编码员的工作台状态）

**画面构成**

- 窗口顶部是**今日批次条**：「待复核 7 · 已复核 12 · 已提交 12」。
- 右侧一枚小徽章：「RIS 推送已连接 · 3 条待处理」。
- 中间仍是同一张对照表：已确认的行左侧打勾并变灰（已提交），未处理的行留在原位。
- 右下角一个**可收起抽屉面板**，标题「本次复核证据清单」：每条证据一行，写明来源系统、接收时间、证据哈希前 8 位、「已引用 2 处」。
- 系统托盘图标变**蓝**，hover 显示「已连接 · 待处理 3 · 今日已提交 12」。

**视觉语言**

| 项 | 值 |
|---|---|
| 托盘蓝 | `#1A6FD4` |
| 抽屉面板 | `#FFFFFF` 面板 + `#E3E6EA` 分隔线 |
| 哈希 / 时间戳 | 等宽小字 `Menlo / Consolas` 11px；正文仍用中文字体 |
| 信息层级 | 批次条 → 差异行 → 证据抽屉 |
| 留白密度 | 中等；表行高 30px，抽屉占 1/4 宽 |

## 必须可达的约束

只允许现有技术栈**真能做出来**的元素：

- 全部元素限于 **Java 17 + Swing**（`JFrame` / `JTable` / `JSplitPane` / `JTextArea` / `SystemTray` + `TrayIcon`）+ **本机 SQLite**；
- **不画**任何 WebGL / 3D / 动画过渡 / 自定义矢量插画；
- 表格用 Swing `JTable` + `DefaultTableCellRenderer` 即可实现徽章与左侧竖条，**不引入图表库**；
- 「实时刷新」靠监听线程（MLLP 入站）→ `SwingUtilities.invokeLater` 回主线程刷新表格，**不承诺动画过渡**；
- 托盘图标用 `BufferedImage` **程序化绘制**（纯色方块 + 计数文字），**不使用外部图片资源**；
- 打印 / 导出（PDF、CSV）不在本轮视觉目标内——如实现，须真实导出后才可进入「成形态」，否则不上这张卡；
- 字号、间距、色值统一由设计 token 提供，**界面代码里不散落硬编码色值**。

## 与实测的差距（诚实标注，写给 README 用）

- 目标卡描述的是**理想的信息密度与徽章质感**；真实实现受 Swing 默认组件限制，徽章圆角、阴影、行高未必与目标完全一致。
- 目标卡的「成形态」依赖托盘 hover 提示、批次条与抽屉收起态三者同时成立；实现进度落后时实测截图可能只呈现到「首个可用瞬间」。
- README 的「概念 / 实测对照」小节必须写明**哪一侧是目标、哪一侧是实测**，**不得声称两者完全一致**，也**不得**用事后效果图抹平差距。
